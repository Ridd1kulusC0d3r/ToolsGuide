OpenOSINT

Um agente de IA que investiga alvos em fontes abertas com 20 ferramentas reais — e que, por desenho, não consegue inventar achados. Este guia te leva do zero ao primeiro relatório, um nível de cada vez.

A Central Pneumática de Investigação

Antes de qualquer comando, entenda o OpenOSINT como um objeto físico. Tudo que você vai ler abaixo já está nesta bancada: observe uma investigação completa acontecer — ou assuma o controle com o mouse.

Regra da cápsula. A torre (IA) decide; a estação do outro lado do tubo (holehe, sherlock, HIBP, Shodan…) responde. A cápsula só carrega o que a estação de fato devolveu. Esta separação é a frase mais importante do projeto: “the AI issues hard-stop tool calls; your code executes the real binary”.
Nível 1: explique para uma criança →
1Feynman · explique como para uma criança

O que é isso, em uma frase?

É um detetive-robô de fontes abertas: você entrega um e-mail, username, domínio, IP ou nome, e ele mesmo decide quais das 20 lupas usar, usa uma lupa, olha o que achou, escolhe a próxima lupa por causa do achado — e no fim te entrega o caderno do caso (relatório em Markdown e PDF).

🧒 Para a criança

“É um correio de tubos: eu escrevo um nome num cartão, o robô da torre manda o cartão pelo tubo certo, e a resposta volta voando dentro de uma capsulinha. Se a resposta tiver outro nome dentro, o robô manda esse nome por outro tubo.”

🔬 Para o colega de SOC

Agente LLM (Claude, Ollama local ou qualquer endpoint OpenAI-compatível) com 20 tools determinísticas de recon passivo, encadeamento autônomo por achados, execução paralela via asyncio.gather(), histórico de sessão e servidor MCP nativo.

2Feynman · encontre as engrenagens

O mapa da máquina

Quatro portas de entrada, um cérebro, vinte braços, e duas saídas. A seta tracejada verde é o movimento que diferencia esta ferramenta de um simples “menu de scripts”: achados voltam ao agente e viram novas consultas.

As 4 portas

REPL — console de conversa (openosint). Web UI — chat no navegador com cartões de resultado (openosint web). CLI — ferramenta direta, sem IA (openosint email …), perfeita para scripts e pipelines. MCP — as 20 tools dentro do Claude Code/Desktop, Cursor e afins.

Os 3 cérebros possíveis

Anthropic Claude (padrão, requer ANTHROPIC_API_KEY), Ollama (100% local, sem chave — llama3.2 por exemplo) ou qualquer endpoint OpenAI-compatível (LiteLLM, vLLM, LM Studio). A máquina é a mesma; só a torre muda de cérebro.

Instalação guiada

Escolha sua aba, copie, cole, pronto. Nenhuma chave de API é necessária para começar — mais de 10 ferramentas já funcionam no primeiro minuto.

Passo 1 — instale o uv uma única vez (ele isola tudo, sem bagunçar seu Python):

# macOS / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Passo 2 — abra um terminal novo e suba a interface web:

uvx openosint web

O navegador abre em http://127.0.0.1:8080. Se a porta estiver ocupada: uvx openosint web --port 8081.

Passo 1 — Python 3.10+ e o pacote:

pip install openosint

Passo 2 — escolha sua porta de entrada:

openosint              # REPL com IA (padrão)
openosint web          # interface no navegador
openosint email alvo@example.com   # ferramenta direta, sem IA

Passo 3 (opcional) — binários externos que destravam 4 ferramentas:

pip install holehe sherlock-project sublist3r
# phoneinfoga: baixe o binário em github.com/sundowndev/phoneinfoga/releases

Sem um binário, a ferramenta correspondente devolve um erro descritivo — o resto segue funcionando.

Passo 1 — instale o Python 3.10+ pela Microsoft Store ou python.org (marque “Add to PATH”).

Passo 2 — no PowerShell:

pip install openosint
openosint web

Para o grafo de entidades no Windows, use a aba Docker — a extra [graph] exige compilar PyICU, e a imagem Docker já vem com tudo.

git clone https://github.com/OpenOSINT/OpenOSINT.git
cd OpenOSINT
docker compose up --build
# comando avulso:
docker compose run --rm openosint email alvo@example.com --json

A porta é publicada só em 127.0.0.1 e a imagem já inclui a visão de grafo. Relatórios caem em ./reports/; banco do grafo e histórico vivem no volume openosint-data.

git clone https://github.com/OpenOSINT/OpenOSINT.git
cd OpenOSINT
pip install -e .
# atualizar instalação via pip:
pip install --upgrade openosint
Primeiro minuto, zero chaves: já funcionam generate_dorks, search_dns, search_whois, search_domain, search_email, search_username, search_paste, search_phone, search_gdelt_geo — e search_ip / search_github com limite de taxa. O chat com IA precisa de ANTHROPIC_API_KEY ou um Ollama local.

7Operação avançada

Os quatro modos, a fundo

🖥️ REPL — comandos do console
<alvo>investiga qualquer alvo: e-mail, username, domínio, IP, nome
toolslista ferramentas e o status de cada uma (chave ok? binário presente?)
savesalva o último relatório em reports/
clear / config / history / help / exitlimpar memória · ver config · sessões salvas · ajuda · sair
Sessões são gravadas automaticamente em ~/.openosint/history/. Flags úteis: --parallel (ferramentas complementares em paralelo), --json (saída estruturada), -t N (timeout), --no-pdf, -v.
🧩 MCP — as 20 tools dentro do Claude
# Claude Code
claude mcp add openosint python /caminho/absoluto/OpenOSINT/openosint/mcp_server.py
# Claude Desktop → claude_desktop_config.json
{ "mcpServers": { "openosint": {
    "command": "python",
    "args": ["/caminho/absoluto/OpenOSINT/openosint/mcp_server.py"],
    "env": { "OPENOSINT_ENV_FILE": "/caminho/absoluto/.env" } } } }
Depois, em conversa: “Investigue alvo@example.com. Rastreie qualquer username encontrado em outras plataformas e compile um relatório.”
🏠 IA 100% local — sem mandar nada para fora
# requer o runtime Ollama (ollama.com)
ollama pull llama3.2
openosint web          # Settings → Ollama (local) → llama3.2
# ou no REPL/CLI, endpoint OpenAI-compatível:
pip install "openosint[openai]"
openosint --provider openai --openai-base-url http://localhost:4000/v1 --openai-model gpt-4o-mini
Para investigações sensíveis, esta é a configuração que mantém o raciocínio do agente dentro da sua máquina — só as consultas das ferramentas tocam as fontes.
🛡️ Segurança do Web UI — leia antes de expor
Nunca exponha o Web UI na rede com suas chaves no ambiente. Desde a v2.28, com bind fora do loopback (--host 0.0.0.0 + --allow-remote), o servidor se recusa a usar chaves do seu .env para servir terceiros e desativa search_breach — cada visitante precisa trazer a própria chave.
Atrás de reverse proxy (nginx, Caddy, túnel): requisições com cabeçalhos de encaminhamento são tratadas como públicas por padrão. Só defina OPENOSINT_TRUSTED_PROXY=true se você escolheu servir consultas credenciadas a quem o proxy repassar — e coloque autenticação real na frente. Hostnames alternativos entram em OPENOSINT_ALLOWED_HOSTS; front-ends em outra origem, em OPENOSINT_ALLOWED_ORIGINS.
🕸️ Grafo de entidades (opcional) — proveniência por afirmação
Um grafo FollowTheMoney aditivo: armazenamento append-only, cada afirmação carrega dataset, extrator, execução e confiança, e deduplicação same_as não destrutiva com fila de revisão humana. Instale com pip install "openosint[graph]" (Python 3.10+; [graph-dedup] pede 3.11+ e pontua candidatos). Três tools MCP: graph_export (gera .ftm que passa em ftm validate), graph_neighbors, graph_review_candidates. Lembre: aresta same_as é candidata pontuada, nunca identidade verificada.
Teste final de Feynman →
8Feynman · ensine de volta

Você consegue explicar?

Quatro perguntas. Errar aqui é barato — errar numa investigação real, não. Clique e receba o porquê.

0 / 4 corretas

1. Na analogia da central pneumática, quem é a torre roteadora?

A torre não investiga nada sozinha: ela lê o alvo, decide o tubo e despacha. Investigar é trabalho das estações (as 20 ferramentas) do outro lado.

2. Por que “achado alucinado é estruturalmente impossível” no OpenOSINT?

É o desenho da cápsula: a IA aponta o tubo, mas o que volta dentro da cápsula é o que a estação real respondeu. A IA ainda pode escolher mal os tubos — mas não pode inventar o conteúdo.

3. Você instalou agora, sem nenhuma chave de API. O que funciona?

Metade do arsenal roda de graça: generate_dorks, search_dns, search_whois, search_domain, search_email, search_username, search_paste, search_phone, search_gdelt_geo, e search_ip / search_github com limite de taxa.

4. O que um resultado negativo (ex.: “nenhum vazamento encontrado”) significa?

Regra de ouro de inteligência: ausência de evidência não é evidência de ausência. Cada tubo responde só pelo que a estação dele enxerga.

📝 O último passo do método

Feynman dizia que você só entendeu quando consegue ensinar. Então: abra o terminal, rode openosint contra um alvo seu (seu próprio e-mail é o laboratório perfeito e 100% autorizado), e escreva três linhas explicando o relatório para alguém que nunca viu a ferramenta. Travou em alguma linha? O capítulo correspondente está na navegação lá em cima.

⚑Solução de problemas e limites honestos

Quando algo não funciona

“ferramenta X retornou erro de binário ausente”
holehe, sherlock, sublist3r e phoneinfoga são subprocessos externos que precisam estar no PATH. Instale-os (aba Instalar, passo 3) — e mantenha-os atualizados você mesmo: o OpenOSINT não os corrige nem audita.
“porta 8080 ocupada”
O OpenOSINT sai e avisa. Use openosint web --port 8081.
“chat com IA não responde”
Verifique o provedor: ANTHROPIC_API_KEY no .env para Claude, ou Ollama rodando (ollama pull llama3.2) para o modo local. No REPL, config mostra o que está carregado.
“cadê meus relatórios e meu histórico?”
Relatórios do REPL/CLI: ./reports/ no diretório de onde você rodou (o Web UI não grava relatórios). Histórico e banco do grafo: ~/.openosint/ (%USERPROFILE%\.openosint no Windows); mova tudo com OPENOSINT_HOME=/caminho.
“o servidor MCP não acha minhas chaves”
O host MCP inicia o processo com cwd arbitrário. Defina OPENOSINT_ENV_FILE no bloco env da configuração do cliente — é a única opção garantida.
“proxy configurado funciona?”
openosint proxy-test verifica o proxy de saída configurado.

Limites que o próprio projeto declara

• Uso autorizado apenas. A ferramenta consulta fontes públicas e semipúblicas; não burla autenticação nem explora sistemas. A responsabilidade legal — LGPD inclusive — é sua.
• Resultado negativo ≠ ausência de exposição: significa que aquela fonte não reportou correspondência.
• 9 das 20 ferramentas dependem de terceiros (uptime, limites e preços dos provedores, não do OpenOSINT).
• O agente só enxerga as 20 ferramentas: não navega a web livre nem executa código arbitrário — a seleção de tubos ainda pode ser incompleta para um alvo específico.

Glossário

OSINT
Open Source Intelligence — inteligência produzida a partir de fontes abertas e legalmente acessíveis.
Agente
Programa que usa um LLM para decidir, em loop, qual ação executar a seguir com base nos resultados anteriores.
Tool call
Chamada estruturada que o LLM emite; o código do OpenOSINT a executa de verdade e devolve o resultado bruto.
Pivô
Usar um achado (ex.: username descoberto num e-mail) como novo alvo da próxima consulta.
Dork
Consulta avançada de buscador (site:, intext:, filetype:) que filtra resultados com precisão cirúrgica.
Breach
Vazamento de dados; o HIBP indexa quais e-mails apareceram em quais incidentes.
MCP
Model Context Protocol — padrão que expõe as 20 ferramentas a clientes como Claude Code, Claude Desktop e Cursor.
REPL
Read-Eval-Print Loop — o console interativo que abre ao rodar openosint sem argumentos.
E.164
Formato internacional de telefone (+5531999999999) exigido pelo search_phone.
SERP
Search Engine Results Page — a página de resultados do buscador, coletada pelas ferramentas Bright Data.
FollowTheMoney
Modelo de dados de entidades (pessoas, empresas, contas) usado pelo grafo opcional, com proveniência por afirmação.
same_as
Aresta candidata do grafo dizendo “estas duas entidades talvez sejam a mesma” — pontuada para revisão humana, nunca automática.
